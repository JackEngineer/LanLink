# LANLink architecture cross-judgment

The goal is a local-only macOS and Windows app with bilateral pairing, durable chat, resumable files, and honest release evidence. I read the complete brief and all four candidate files. These scores judge the proposed designs, not implemented or tested behavior.

Choose **Sol as the implementation base**. Its immutable sender spool, sequential receiver offset, private opaque storage, per-peer authorization gate, and per-transfer file ownership form the smallest coherent implementation. Take the specific recovery and cancellation details below from Astra. Do not combine both ownership models or add IK for this release.

## Essential changes to the selected base

1. Adopt Astra's explicit revoke completion barrier. Under the peer gate, invalidate the session lease and commit the new trust epoch. Release that gate, then cancel and join the peer's network and transfer tasks before replying successfully. Workers must be able to exit without taking a gate held by their waiter. A database failure leaves the live connection cancelled and reports failure. Reauthorization always requires durable active trust. Bytes already transmitted remain outside the guarantee.
2. Adopt Astra's framing cancellation rule. A partial read must survive selection-loop interruption through a persistent decoder, or the socket must close. Any cancelled or timed-out partial ciphertext write closes the socket. No caller retries a partially encrypted record on that transport. Keep one owner per direction and serialize access to the Noise state.
3. Make filesystem durability explicit. Creating a new private blob requires durable directory metadata before an acknowledged offset can depend on its existence. Validate the platform-specific durability mechanism on macOS and Windows. File-content sync alone does not establish this part of the proposed contract. On a missing or shortened acknowledged blob, show a recovery failure and offer restart from zero. Do not silently present the old acknowledged progress as valid.
4. Define finalization once. Sol publishes a verified, synced private blob through a committed Complete row. That provides atomic application visibility and avoids a rename/database window. It does not itself promise an atomic file appearing in a user's chosen directory. For this smallest release, make the retained private blob the received file and make user export an explicit later action. If the user-facing contract requires automatic destination export, use Astra's persisted finalization intent, same-filesystem no-replace publication, directory durability, and restart reconciliation before Complete. Do not claim that a database flag proves external filesystem publication.
5. Bind every retry to its full manifest and peer epoch. Persist cancellation and completion receipts. Reject a reused message ID with changed content and a reused transfer ID with changed manifest. A revoked peer that is paired again gets a new epoch and no automatic revival of earlier accepted transfers.
6. Write actual limits into configuration and tests. Sol names the right limit categories but gives few numeric budgets. Bound handshakes, discovered records, paired peers, queued frames, offers, uploads, active transfers, staging bytes, retained completed bytes, and database growth. Admission can fail visibly when a bound is reached. No automatic deletion of user history is necessary to implement a bound.
7. Add an explicit P1 through P7 verification and commit mapping. None of the candidates supplies the brief's required phase mapping. Keep Windows native packaging and real two-machine tests as open release gates until executed. A two-process Mac test is useful evidence for protocol behavior but cannot close those gates.

## Candidate-specific dangerous choices

Sol's strongest choice is keeping file bytes under an opaque private path and publishing through SQLite. Its dangerous ambiguity is calling that filesystem finalization without distinguishing application publication from external export. Its revoke response currently waits for commit but does not explicitly wait for worker termination. Its proposed automatic reset after a missing acknowledged blob needs visible failure reporting. Its assertion that a global actor necessarily queues revoke behind disk work is too broad. Astra expressly keeps file I/O outside its actor.

Astra's global command actor gives the reader one place to inspect durable authorization decisions. It becomes dangerous if the implementation waits inside that actor for workers whose termination needs another actor command. Its bounded mailbox also needs fairness or a control path so file progress cannot indefinitely delay revoke. The document's no-replace finalization is the best external-export sketch, but it still needs an exact persisted intent and reconciliation algorithm for each crash window. Its automatic transition from an incomplete reconnect into fresh pairing is more stateful than Sol's explicit repair. Keep repair explicit.

Terra leaves a race between revocation authorization checks and durable commit unless every relevant mutation shares its peer registry's serialization boundary. An in-memory generation check at dispatch is insufficient if revocation commits while a message insert is already in progress. Its source reread can work only with a specified immutable-source guarantee or complete content revalidation. Adopting Sol's staged snapshot is simpler. The candidate also has two Noise handshake paths and a SAS derived solely from a truncated handshake digest. Neither the security level nor the adversarial generation strategy for that SAS is specified. Do not ship it as a reviewed comparison protocol.

Luna's proposed five decimal digits cannot represent the stated first 20 bits without an additional reduction rule. It also omits commitment exchange, so the intended SAS security bound is unspecified. `INSERT ... ON CONFLICT DO NOTHING` followed by ACK accepts a conflicting payload unless the existing row is compared. That is a concrete deduplication defect in the proposed algorithm. Chunk bitmaps add complexity to an otherwise sequential transfer. Its rename then Complete commit lacks a persisted finalization intent or reconciliation rule for a crash between those steps. Cancellation without a durable epoch and a commit barrier leaves the revoke guarantee unproven. The bearer bootstrap and browser WebSocket authentication need a concrete flow, which Sol already provides.

## Smallest design to implement

Keep one Rust process, SQLite WAL with FULL synchronization, static same-origin React assets, one Noise XX protocol for pair and reconnect, and the versioned commitment-and-reveal comparison proposed by Sol. Pin only after both users approve the exact live session, and exchange Ready after durable trust. Treat the custom comparison exchange as a protocol requiring adversarial tests, not as security inherited automatically from Noise.

Use concrete domain commands shared by HTTP and network handlers. Serialize authorization-sensitive database transitions under one gate per peer. Every network lease carries peer, epoch, and full session identity. Use one bounded connection writer and one file owner per transfer. Keep hashing and file I/O outside the peer gate. Join an old file owner before starting a replacement.

Persist sender snapshots, accept each received manifest once, transfer a contiguous offset in approximately 60 KiB records, and ACK only after file sync followed by the offset commit. Use no bitmap, no out-of-order chunk scheduler, no resume of Noise keys, and no second generic service layer. Publish verified private files through Complete rows and keep completed receipts for reconnect. Select an explicit export policy before claiming external filesystem publication.

Use exact Host and Origin checks, a launcher-delivered per-boot bearer, and one-use WebSocket tickets. UI events invalidate queries. An event gap or reconnect triggers refetch. Keep Zustand limited to local interaction state. The UI shows real agent data and distinct pairing, delivery, and transfer states.

The Make Operations Idempotent principle changed the recommendation toward stable IDs, immutable spools, terminal receipts, and explicit finalization reconciliation. The Minimize Reader Load principle changed it toward one handshake path, a single contiguous offset, and concrete commands instead of additional generic layers. I read both principle leaf skills for this review.

No implementation was changed. The decisive next check is a protocol and persistence test plan that injects a crash at every sync, commit, publication, and ACK boundary, plus revoke races against those same transitions.
