# LANLink candidate architecture

Use a single Rust process per device and a static React SPA served by its loopback HTTP server. Keep direct, bounded services instead of a global actor. A connection task owns each Noise transport and its send queue; shared services hold a SQLite pool and cancellation tokens. A small peer registry serializes connection replacement and revoke per peer. SQLite transactions define durable state. File I/O runs outside database transactions. This keeps concurrency explicit without routing every operation through a single mailbox.

## Modules and data

- `identity`: durable randomly generated Noise static private key and derived public key. A device ID is the hex SHA-256 of the public key. Store private key in an owner-only file, reject invalid permissions where supported, and exclude it from logs. Display name and OS are mutable metadata, never identity.
- `discovery`: mDNS advertises device ID, name, OS, protocol version and actual TCP port. Treat all discovery properties and addresses as hints, including own-ID collisions. Limit metadata and peers.
- `db`: migrations and typed repositories. Tables: `peers(id, public_key, name, approved_at, revoked_at)`, `messages(id, peer_id, direction, body, state, created_at)` with unique `(peer_id,id,direction)`, and `transfers(id, peer_id, direction, name, size, sha256, state, committed_offset, temp_path, final_path)` with unique `(peer_id,id,direction)`. SQLite WAL, foreign keys, busy timeout and bounded transactions. All external records are parsed and size-limited before persistence.
- `protocol`: versioned length-prefixed encrypted frames, bounded decode, typed messages (`Approval`, `Chat`, `ChatAck`, `Offer`, `Accept`, `Chunk`, `ProgressAck`, `Complete`, `Cancel`, `Error`). Each Noise ciphertext is at most 65535 bytes, including authentication tag. Fragment a logical 1 MiB file chunk into smaller independently encrypted frames with transfer ID and absolute offset. Reject gaps, integer overflow and oversized allocations.
- `session`: listener, outbound dial, handshake, peer-scoped encrypted writer and reader; cancellation closes the socket. Deterministic connection tie-break based on device IDs avoids duplicate active sessions. Retry with jitter and bounded queues. Runtime sessions are disposable; durable jobs are recovered from SQLite.
- `pairing`: pending attempt IDs and states `Handshaking -> AwaitingLocalApproval -> AwaitingRemoteApproval -> Paired | Rejected | Expired`. Local UI exposes compare-and-approve and reject; timeouts and cancellation delete ephemeral state. The peer never becomes authorized from mDNS alone.
- `messaging`: commands persist outgoing message and stable UUID before send. Receiver inserts or finds the message within a transaction and sends ACK only after commit. ACK identifies message and peer. Sender marks sent only on valid ACK; unacknowledged messages retry using the same ID after reconnect or restart. Duplicate receives re-ACK without duplicate history. Transport errors update pending/failed visibly; retry reuses ID.
- `files`: an offer persists metadata and requires a fresh receiver acceptance per transfer. Validate file size against configurable default 2 GiB and aggregate partial-file quota; reserve bounded space and limit concurrent transfers. Generate local opaque temporary names under a private directory, sanitize display names, prohibit path separators and traversal. Transfer bytes in bounded frames with offsets. Periodically flush and sync data before committing acknowledged offset in SQLite; ACK only the committed offset. On restart reconcile DB offset with actual partial length and truncate to the safe committed boundary before resuming. Sender reconnects and seeks to the receiver's acknowledged offset. Re-read or validate the source before retry so changed files cannot silently complete. At completion verify exact size and SHA-256, sync the temporary file, atomically finalize with a no-replace primitive into an approved destination, sync directory where supported, then persist completion and ACK. Reconcile the rename/DB crash window using persisted finalization intent and an opaque transfer identifier; never overwrite or trust a user-controlled path. Cancel closes work, records cancellation and removes the owned partial file; revoke also cancels active transfers and blocks resume.
- `api`: axum binds IPv4 loopback only at 127.0.0.1:38761 and serves embedded UI. Strictly validate Host against the actual loopback authority and Origin against the exact UI origin for state-changing HTTP and WebSocket requests; reject missing or foreign Origin for browser mutations and WebSocket. Generate a high-entropy per-launch token, deliver it only through the loopback document response, require it in a custom header on mutations and an authenticated WebSocket handshake, and use CSP/no CORS/no caching. This defends browser-origin attacks, not another process with the same OS user privileges. Bound request and event sizes. UI query cache reads canonical state and WebSocket events invalidate queries; Zustand holds only transient selection and dialogs.

## Pairing and session authentication

Use vetted `snow` Noise_XX_25519_ChaChaPoly_SHA256 for initial pairing. Exchange static keys inside the handshake, then calculate the same short authentication string from a domain-separated hash of the completed Noise handshake hash and protocol version. Display it on both devices, identify the discovered name as unverified, and require each user to confirm their own UI. Send the local decision only inside that exact encrypted handshake session; persist a pinned peer only after receiving the remote approval and granting local approval. Reject application frames until both approvals are committed. If either side disconnects before both complete, expire the attempt and require a fresh handshake and comparison. The peer may temporarily show paired if its final approval was lost; subsequent authenticated reconnect can converge only if both have pinned each other, otherwise require a new pairing.

For reconnect use Noise_IK_25519_ChaChaPoly_SHA256 with the responder static key pinned in advance. The responder verifies the initiator static key against its own active peer row after the handshake; the initiator verifies the authenticated responder key and expected peer ID. Bind the protocol/version to the prologue. No application traffic is processed before the DB authorization check. Pairing approval and reconnect must verify peer ID equals the hash of the authenticated static key, not a claimed ID. Enforce rate limits and timeouts, reject malformed handshakes, and avoid logging keys or SAS.

Revoke transactionally marks the peer revoked before cancelling its session and queued operations. Every inbound dispatch and outbound dequeue rechecks an in-memory generation derived from the current peer authorization, invalidated synchronously with revocation; reconnect requires a fresh database check. Already committed history remains, and bytes already delivered cannot be recalled. Re-pairing requires a new SAS approval on both devices and explicit policy for prior history.

## API surface and verification

`GET /api/state`, `/api/peers`, `/api/messages?peer=`, `/api/transfers`; `POST /api/pair/{attempt}/approve|reject`, `/api/peers/{id}/revoke`, `/api/messages`, `/api/transfers/{id}/accept|cancel|retry`, `/api/settings`; authenticated `/api/events` WebSocket. File selection/upload to the agent uses a bounded streaming endpoint and a user-selected save destination through a platform-appropriate picker. Error responses distinguish rejection, offline, quota, file mutation and integrity failure.

Prove parser and authorization boundaries, SAS agreement and mismatches, bilateral approval and reconnect pinning, duplicate delivery and crash-before/after ACK, revocation races, partial writes, restart at every finalization step, malicious filenames, quotas, checksum mismatch and source mutation. Run real two-machine macOS and Windows discovery, bilateral pairing, bidirectional messages, restart, revocation, interruption/resume and 1 GiB transfer tests before calling v0.1.0 complete. Package and startup integration require native platform tests.
