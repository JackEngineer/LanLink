# LANLink architecture candidate

Build one Rust agent that serves the Vite production build from Axum and runs an independent, Noise-encrypted LAN listener. The browser renders actual agent state and can close without stopping delivery. SQLite owns durable application state. Each connection owns its Noise state. One keyed mutex per peer orders authorization-sensitive mutations, and one worker per transfer exclusively owns its file handle across connection changes. Cancel and join the previous worker before reopening a partial blob. No global application actor is necessary. A single mailbox would put revocation and chat behind unrelated disk operations.

## Contracts and ownership

```rust
DeviceId([u8; 32])  // SHA-256 of persistent X25519 public key
PeerEpoch(u64)
MessageId(Uuid)
TransferId(Uuid)
SessionId([u8; 32]) // full Noise handshake hash
Lease { peer: DeviceId, epoch: PeerEpoch, session: SessionId }
Link = Pairing(PairingState) | Ready(Lease)
ChatStatus = Pending | Sending | Sent | Failed
TransferStatus = Offered | Accepted | Transferring | Verifying
               | Complete | Declined | Cancelled | Failed
```

- `identity` creates a static key in a private per-user data directory and persists it before advertising. It fails visibly if an existing identity cannot be read. `discovery` binds the preferred TCP port or an OS-assigned fallback first, then registers the actual port with `mdns-sd`. The registry contains expiring address hints keyed by device ID. TXT attributes and names are untrusted until confirmed on the encrypted link.
- `wire` handles versioned framing, Noise, and bounded deserialization. Typed pairing frames and application frames use separate state handlers. Read and write tasks own the TCP halves and share the Noise transport state only while encrypting or decrypting. Bounded queues apply backpressure. A timeout or malformed frame closes the socket.
- `peer` holds pending comparisons, active session leases, per-peer gates, cancellation handles and reconnect backoff. Both sides deterministically prefer a connection dialed by the lower device ID and then compare the full session IDs to break duplicate ties. Only the winning lease can deliver or mutate application state. Dial either direction when necessary for asymmetric discovery.
- `store` exposes concrete SQLx operations for trust, history, outbox, transfers and settings. Mutable records carry a peer epoch. SQLite uses WAL, foreign keys and `synchronous=FULL` on its writer. A pinned row records `device_id, key, epoch, state`. Revocation cancels the current lease under the peer gate, advances the durable epoch and disables unfinished old-epoch work. Report success after commit and surface persistence failures. Revocation and application writes use the same gate. A worker may stage private bytes outside the gate, then must revalidate its lease before checkpointing, ACKing or publishing. The writer checks lease cancellation when dequeuing and during socket writes. Already transmitted bytes cannot be recalled. [SQLite WAL durability](https://sqlite.org/wal.html)
- `chat` and `transfer` own typed transitions. Axum and the wire handlers call the same commands. Workers report invalidations after durable transitions. Zustand owns transient UI state and TanStack Query owns fetched data.

## Pair and reconnect

Use fresh `Noise_XX_25519_ChaChaPoly_SHA256` on each socket. Include a fixed LANLink protocol version and explicit pair/reconnect mode in the prologue. At handshake completion take the full hash `h` and remote static key from Snow. Compute the remote ID from that key, check an expected dial target if supplied, and reject self identity. Exchange bounded display metadata inside the cipher. In reconnect mode require an active exact-key pin before sending `Ready(h)`. Reject an unknown, revoked or changed key and do not fall back into pairing. [Noise protocol](https://noiseprotocol.org/noise.html), [Snow handshake builder](https://docs.rs/snow/latest/snow/struct.Builder.html)

For an explicit pairing, exchange commitments to fresh 32-byte random nonces before revealing either nonce. Use `SHA256(domain_commit || h || role_byte || nonce)` and reject a bad opening. After both openings, display the first 40 bits of `SHA256(domain_sas || h || initiator_nonce || responder_nonce)` as ten grouped hex digits. The domains are distinct protocol-versioned constants and all fields have fixed lengths. Committing before either opening fixes each side's input before it learns the other nonce. Reserve one local pairing slot before sending a commitment and release it on Ready, timeout or disconnect. Bound the rate and concurrency of unauthenticated handshakes. [Bluetooth Numeric Comparison reference for nonce commitments](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/Core_v7.0/out/en/br-edr-controller/security-sec--specification.html)

Each UI approval refers to the full session ID, expires with that socket, and sends encrypted `Approve(h)`. A rejection closes the attempt. After local approval and matching authenticated remote approval, atomically persist the pin, then send encrypted `Ready(h)`. Admit application frames only after both Ready messages. A crash can leave one device with a pin after both humans approved. Its next reconnect still requires remote Ready and fails closed if the remote never stored the pin. The users can explicitly compare a new code to repair. Reconnect always starts new cryptographic state. Only application state resumes.

## Chat and files

A send request carries a stable message UUID. Its SQLite insert creates a pending outgoing message before the UI reports success. The worker sends pending rows on a ready lease and may mark sending for display. On receive, check epoch and insert the incoming message transactionally. A repeat with identical peer, ID, and payload returns the existing receipt. A conflicting duplicate fails the protocol. Send `MessageAck(id)` only after commit. The sender accepts an ACK for the matching peer and outgoing UUID, then commits Sent. Restart converts stale Sending to Pending. Connection loss requeues unacknowledged sends with backoff. Permanent errors become Failed with an explicit retry command using the original UUID.

Stage an outgoing browser upload as a private immutable blob while streaming its SHA-256. Enforce a declared byte count and the configured cap, default 2 GiB, during upload. Persist metadata only after verifying the count and syncing the file. The offer carries `{id, safe_display_name, size, sha256}`. Authorize acceptance separately per inbound transfer, then reserve the bytes in SQLite before permitting any payload. Reserve outgoing upload space too. Bound aggregate stored and reserved bytes and concurrent uploads, transfers and outstanding offers. Retain partial blobs across disconnect and release reservations and private files on terminal cancellation or expiry. Completed downloads count against the quota until deleted.

Use one sequential logical chunk at a time, default 1 MiB. Fragment each into raw binary records with the transfer UUID, offset and bounded payload, for example 60 KiB per record. A u16 ciphertext length frames each Noise record. Check the complete encoded plaintext plus the 16-byte tag against 65,535, including metadata. Control frames use a bounded Serde format. Reject invalid offsets, chunk sizes and data above the accepted size before writing. [Snow transport size limit](https://docs.rs/snow/latest/snow/struct.TransportState.html)

For each chunk, write consecutive fragments to the private blob, sync the file and commit the durable offset before ACK. The sender never has to retain a chunk in memory after reading it from its immutable spool. On reconnect the receiver returns its committed offset or terminal receipt. Startup truncates a longer unfinished blob to its committed offset. A missing or shorter blob resets that transfer to offset zero after creating and syncing a fresh blob. Retrying an offer yields the persisted acceptance or final result only if its metadata matches. Cancellation is durable, retains a tombstone, and is sent again on reconnect until acknowledged. Resume uses the same transfer ID and accepts only the current epoch.

On the final chunk, transition to Verifying and hash the closed-for-write blob without holding the peer gate. Recheck the lease before committing Complete. A bad hash fails the transfer and removes the bad blob. Stage and final storage use the same opaque file created exclusively under a private, app-owned root. The database commit atomically publishes the synced file by making only Complete rows eligible for streaming download. Display names never become on-disk paths. Strip path separators, control characters and Windows reserved names for Content-Disposition, with a generic filename fallback. Browser download handling owns the separate user-facing save and collision behavior. Retain the received blob and completion receipt across restarts. Delete staged blobs without database references on startup, and return the same completion receipt after a dropped final ACK.

## Local API and verification

Serve all production assets and routes on `127.0.0.1:38761`. Require the exact Host and loopback TCP peer. Match Origin exactly when present, and require it for WebSocket and browser mutations. Do not enable CORS. Issue a random per-boot bearer privately to the native launcher, use the URL fragment for browser handoff and immediately remove it from the URL. Store it in session scope. Serve public static assets only, with CSP and frame protection. Protect state and mutations with the bearer. Issue single-use short-lived WebSocket and browser-download tickets through bearer-authenticated REST, avoid logging ticket values, and check the WebSocket Origin before upgrading. Expose devices, pair decisions, history/send/retry, streamed transfer upload, accept/cancel/download, settings and revoke. Treat WebSocket events as query invalidations and refetch on reconnect and lag. Keep production origin checks identical in packaged builds.

Verify pairing decline, stale approval, one-sided commit and changed keys before messaging. Test a lost message ACK and restart without duplicate history. Test partial-fragment crash, offset commit before ACK, hash failure, cancel and revoke during transfer, and disk quota exhaustion. These local checks support implementation. Release evidence still requires real macOS–Windows discovery, bilateral pairing, messages both ways, a 1 GB transfer, restart, revocation and failure handling, plus installer and optional login-startup checks on their native platforms.

Model the Domain drives the explicit Pairing and Ready states and typed transfer transitions. Make Operations Idempotent drives message IDs, offset checkpoints, durable cancellation, completion receipts and startup reconciliation.
